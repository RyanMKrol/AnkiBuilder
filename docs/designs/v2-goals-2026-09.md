# v2 goals

The reference doc for whether v2 is achieving what it set out to. v1 is preserved at git tag `v1`.

## Context

v1 works: 34 units, 2,453 reviewed cards of _Japanese for Busy People Book 1_, delivered to a
collection studied daily. It got there by accretion, and three things about how it got there are what
v2 exists to fix.

**The model calls ended up in the wrong place by accident.** Git history, all on 2026-07-13:
`Initial commit`, then `Add implementation harness`, then `Add MVP pipeline backlog (T002-T011)`, then
`T005: Translation stage via local claude -p`, then `Package the deck-builder as a project-local
Claude skill`. An autonomous harness was building a CLI from a task list. There was no operator agent,
so a pipeline that needed a model had to spawn one itself. The harness retired, an operator agent
replaced it, and the arrangement was never revisited.

**Scripts make judgements they are not equipped to make.** `vocabCoverage` decides what a vocabulary
table is by matching `class="voca"`. On any other book it returns `[]`, reports zero uncovered
headwords, and prints clean. **There is no promise an EPUB will ever be internally consistent**, let
alone consistent with another book, so structural pattern-matching is the wrong tool for every
semantic question in the pipeline.

**Rules do not travel between passes.** `card-authoring-rules.md` claims it governs "every pass that
writes cards", but nothing makes that true. Verified: the extraction prompt protects irregular forms
from sampling, `docs/semantic-dedup-prompt.md` never mentions _irregular_, _exception_, `する` or
`くる`, and `chapter-17/fib-ryouri-suru-mae-te-araimasu` was mined correctly and then deleted as a
"third+ example of a frame the source teaches twice".

## The governing principle

**The whole workflow is modelled as scripts. A step in a script always runs; an agent that decides for
itself whether to do something does not.**

That is what buys deterministic orchestration over non-deterministic steps. It is also the limit of
what it buys: `claude -p` guarantees the _call_ happens, never that the output is good. Every step's
result is therefore verified by its **artifact**, not by its exit code or its own report.

## The product

One Claude skill with three pathways, plus a second skill that onboards a new EPUB.

1. **Extend an existing EPUB deck**, building the next chapter of a book in progress.
2. **Augment an EPUB deck** with content from an in-person or side lesson.
3. **Ad hoc deck from a corpus**: the user supplies content, or describes scenarios and the agent
   proposes a corpus.

Pathway 2 keeps its **per-card** additions gates (`additionReviewed` / `additionDone`). This is not an
inconsistency to iron out. It exists because the first absorption cleared `done` on fifteen finished
units to approve a dozen new cards each. 35 cards sit at that gate right now.

## The workflow

Three phases, strictly sequential, one chapter at a time. Each phase is **one script**, and each ends
by opening its review and arming a watcher.

```
1. BASE      chapter -> vocabulary corpus -> CORPUS REVIEW (base)
2. EXTRAS    approved vocabulary + grammar -> sentence corpus -> CORPUS REVIEW (extras)
3. AUDIO     both units -> ElevenLabs -> AUDIO REVIEW -> deliver
                                     -> LEARNING PASS (see below)
```

**Three gates per chapter, down from v1's four.** v1 ran base, corpus review, audio, done, and _then_
started extras as a whole second arc months later. The ordering was right. What made it expensive was
audio and gate 2 sitting between the two units, so moving audio to the end keeps the rationale and
drops a gate.

Sequencing extras after the base review also dissolves a problem a parallel build would create: extras
sentences are authored against vocabulary a human has **already approved**, so excluding a base card
can never orphan an extras sentence built on it. And no TTS credit is spent on a card that might be
cut.

The dashboard stays a long-running server; the review handoff is a step inside each phase script.

## Division of labour

| Layer                                   | Does what                                                                                                                                                                                      |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Main thread** (Claude Code, Opus 5)   | invokes the phase scripts; confirms from the run report and the artifacts that every step ran and produced something; handles fixups the scripts flag. It does not author content.             |
| **Phase scripts** (Node)                | model the entire workflow: ordered steps, each either a deterministic operation or a pinned agent. Steps cannot be skipped because they are steps.                                             |
| **Agents** (`claude -p`, always pinned) | every semantic judgement: which tables are vocabulary, what an image contains, what counts as a headword, what earns a card, whether two items are really duplicates                           |
| **Deterministic operations**            | supply raw material and compute set operations: dump every table, pull every image, emit bounded chapter text, diff item lists, compute coverage gaps, validate schemas, mint ids, order units |

**There is no separate subagent mechanism in the pipeline.** Every model call is a pinned `claude -p`
invoked by a script step. Claude Code subagents are not used for pipeline work.

No script decides what a vocabulary table is, what an image carries, or what counts as content.
`vocabCoverage` stops parsing `class="voca"` entirely: a script dumps every `<table>` and an agent
decides. Where a script proposes something (a duplicate group, a collision), it reports and an agent
or a human disposes, keeping the existing "report, never `--apply`" idiom.

## Model pinning, a hard convention

**Every agent invoked by a script is pinned to an explicit model and effort. Nothing ever inherits
from the main thread.** The main thread runs Opus 5, so an unpinned call would silently spend Opus
rates on work Sonnet does well, and pinning is the only reason the scripted tier is cheaper than doing
this in-context.

- Every agent role declares its own `model` and `effort`.
- **Adversary and verification agents are pinned to a higher model than the agents they check.** Two
  reasons: catching an omission is harder than producing content, and using a different model from the
  generator is the cheapest available self-preference debias.
- Pinning is overridable per environment (`ANKI_BUILDER_<ROLE>_MODEL`), never at the call site.
- A role file with no pin is a build error, not a default.

## Verification

Each step emits a **structured run report**: status, model, effort, duration, counts in and out, and
the path of the artifact it produced. The main thread verifies against **the run report and the
artifacts on disk**, never free-text logs.

v1's rule: when a click triggers work, watch the work's _artifact_, not the click. A step that did
nothing can still report success. `LIMITATIONS.md` already records that "readiness is inferred from
markers, so a pass that lies about itself is undetectable".

For the adversary, the check is not "did it run" but "does `candidates/coverage.json` exist, and does
its diff against the corpus have entries". The review gate refuses the link if the artifact is missing.

## Agent rosters

### Phase 1, base vocabulary

| Role                              | Fed by                                                            | Produces                                                                                                                        |
| --------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Table specialist                  | a script dump of every table in the chapter                       | headword/gloss pairs, plus which tables it judged non-vocabulary and why                                                        |
| Chapter reader                    | the full bounded chapter text                                     | vocabulary found anywhere, independent of markup                                                                                |
| Image specialist                  | a script dump of every image                                      | a per-image verdict (content / reference chart / labelled figure / decorative) **persisted whatever it is**, plus transcription |
| Coverage adversary (higher model) | the chapter, **not** the corpus and **not** the extraction prompt | an independent enumeration, diffed against the corpus **in code**                                                               |

**Redundancy is deliberate.** Because no EPUB is reliably consistent, these specialists overlap and
their outputs are **unioned**. A table specialist and a whole-chapter reader will disagree, and the
disagreement is the signal. Union for existence, then dedup. Never majority vote, because in a recall
task the minority report is exactly what you want to keep.

The adversary enumerates rather than being asked "what did you miss?". Asked directly, LLM judges
detect omissions at roughly chance; asked whether each of a list of specific items appears, they
recover usable detection. Absence detection is a set operation and belongs in JS.

Persisting the image verdict fixes v1's sharpest silent failure: `extractChapterViaLlm` returns
`{items, coverage, imageCoverage}` and `epubLlmCorpus.js:22` destructures away all but `items`, so a
skipped table and a chapter with no table are indistinguishable after the build.

### Phase 2, extras

Miners run first and are **unbounded**: if the book contains it, it belongs in the extras unit.

| Role                    | Produces                                                                | Bound                                |
| ----------------------- | ----------------------------------------------------------------------- | ------------------------------------ |
| Exercise miner          | complete sentences from drills and worked examples                      | unbounded                            |
| Fill-in-the-blank miner | resolved drill sentences, no blanks left                                | unbounded                            |
| Example-sentence miner  | Key Sentences, model sentences, dialogue lines worth carding            | unbounded                            |
| Gap author              | driven by `taughtNeverUsed`, the paradigm grid, particle example counts | by the gap list                      |
| **Inventive author**    | sentences **not** in the book                                           | **+20% on what the others produced** |

**The inventive author runs last, and is the only bounded role.** It runs last because it must see
what already exists to avoid inventing a duplicate, and it is bounded because an inventive role with
no ceiling is exactly how a unit fills with padding. 20% is a dial rather than a law, and it is the
number to tune first if extras units come out thin or bloated.

Its one hard constraint is the rule v1 names as "most likely to be broken and the most damaging when
it is": **only vocabulary and grammar from this chapter or an earlier one**, which after phase 1 means
the _approved_ vocabulary specifically.

### Phase 3, audio

No agents. Deterministic derivation plus ElevenLabs, unchanged from v1.

## The learning pass

A final workflow step, after each review, that turns the reviewer's own corrections into feedback on
the agents that produced the content.

- Every edit, exclusion and re-wording a human made at a gate is a **free ground-truth signal** about
  where an agent was wrong.
- The step diffs the as-generated corpus against the as-approved corpus, attributes each change to the
  role that produced the item, and reports what that role got wrong.
- Those findings are what feed prompt and roster changes.

**This requires one thing v1 does not have: an immutable as-generated snapshot per unit.** The
dashboard mutates `cards.json` in place (with stamped `.bak` files), so there is currently nothing
durable to diff against. Phase scripts must write the generated corpus to a snapshot the review cannot
touch.

This replaces the v1 eval fixtures for agent-driven work. The fixtures stay for the context-free batch
transforms (romanization, number readings, category assignment, translation), which keep their
recorded-replay seam and remain free to run in CI.

## Content model

**Base is lexical entries.** Single words, bound morphemes (`お〜`, `〜さん`), counters, numbers, and
fixed expressions the book glosses as a unit (`いただきます`, `もういちどおねがいします`).

**Extras is propositions.** Anything with a subject and predicate: Key Sentences, model sentences,
drill examples, dialogue lines, invented practice.

**The test is lexical entry vs utterance, never length.** A fixed expression is an entry at 12
characters; a short clause is an utterance. Do not implement this as a character count.

Today base is 17.7% sentence-length (228 of 1,289 live cards) and extras is already 63% sentences, so
this is mostly a question of what leaves base.

One consequence: every Grammar & Function Words card in base will have no worked example in its own
unit. v1's rule becomes a collection-level obligation satisfied by the extras sibling.
`taughtNeverUsed` already groups base and extras by `chapterNumber`, so it still works and matters
more.

## Generality

**No code may encode knowledge of one specific EPUB**, and no script may make a semantic judgement
about one.

### `book.json`, split into invariants and hints

The seam already exists. `.anki-builder/epubs/<hash>/book.json` is machine-readable, code-authored,
consumed at roughly 15 sites, and already changes parser behaviour per book via
`resolveLabelDecoding()`. It also already has the right pinning discipline: a book's version is frozen
forever once set, because a deck rename in Anki is not a rename.

v2 splits it in two, enforced so a hint can never become a silent code dependency:

- **`invariants`**: facts code may depend on because they really are stable per book. Label decoding,
  lesson-to-spine mapping, image path resolution.
- **`hints`**: what onboarding learned about this publisher, such as "vocabulary tables usually carry
  `class="voca"`" or "exercise blocks are marked by `enum-N` images". These reach **prompts only**, as
  orientation. Nothing branches on them, so a wrong or missing hint costs recall, never correctness.

All three current couplings become hints: `class="voca"`, the `enum`/`wnum` markers, and the English
lesson-label words.

The onboarding skill fills this: ingest an EPUB, analyse where customisation is needed, cross-reference
that against every customisation point the scripts expose, and produce a draft a human reviews and
commits.

### Copy the language plug-in pattern

`getRomanizationLibrary`, `getDefaultVoice`, `getLanguageFont` and `getSimpleScriptRule` are keyed by
ISO 639-1, return a documented empty for an unconfigured language, and the pattern is named in the
code. `romanizationLibraries.js` even records _why_ `ar` and `he` are deliberately absent, with
measured evidence. A config slot that records why it is empty is the best pattern in the repo.

Its two leak shapes are what to forbid for books:

- **Never default the book key.** `?? "ja"` appears in four audit checks and the eval fixtures today.
- **Never let a function make a book-shaped decision without a book argument.** `extrasTools.js` does
  Japanese logic (`か$`, a particle set) with no language parameter at all.

### The load-bearing rule

**A check that finds no configuration for a book reports _unknown_, never _zero_.**
`chapterOutline.js` is the model: its header separates the universal (file bounds, text-vs-image
balance) from one publisher's, and states that an empty result must read as "this book does not number
things".

## What v2 must not break

The data model is **not** changing. Existing cards, corpus definitions and the ElevenLabs integration
stay as they are; v2 changes how they are produced.

1. **`ttsText` string identity.** The audio cache key is `sha256(normalized ttsText + "。ででで")`
   under `<voiceId>/<model>/` and contains nothing else. Keep the derivation byte-identical and a full
   v2 rebuild costs **zero** TTS spend. Changing the marker, the ja whitespace strip, the default
   voice, the model string, or flipping `kanjiTts` globally re-buys roughly 4,400 clips.
2. **Card ids.** `abid:<card.id>` is the durable tag on every delivered note and the `.apkg` guid. New
   ids means every card reads as new, the delivery baseline guard aborts, and recovery is a
   hand-written migration of 2,453 cards' scheduling. This is a harder constraint than the schema.
3. **The two gate flags.** `cards.meta.reviewed` and `cards.meta.done` are read by the dashboard, the
   write-back, the CLI audio gate, package selection, delivery, `gateState`, the watchers and four
   audit checks.
4. **`unitDeckSegments` deck naming**, including zero-padding and the rule that a card-holding deck
   never has children.
5. **The 1,264 hand-curated takes** exist only in run dirs, never in the cache, and ElevenLabs is
   non-deterministic. They cannot be regenerated at any price.

## Non-goals

- **No retroactive rewriting.** Chapters 0-16 keep v1 conventions. Backward dedup and the taught index
  still read v1-format units.
- **No schema redesign**, beyond the as-generated snapshot the learning pass needs.
- **No cross-collection anything.** Golden rule 7 stands; the Nihongo absorption is not a precedent.
- **No rewrite of the back half.** `src/audio` is ported verbatim, and `src/deck/collection.js`,
  `src/anki/` and the audit _framework_ are proven and better-tested than the half being replaced.

## Chapter 17

Delete and rebuild under v2. It reached gate 1 and stopped (`reviewed: true`, no `done`, no audio, no
extras sibling) and it was **never delivered**: its only five ids in `deliveredCardIds` are collisions
with earlier units, and they are exactly the five cards backward-dedup excluded. The v1/v2 seam sits
between chapter 16 and 17.

**Sequencing.** `V2-MIGRATION.md` forbids the `v2` branch from touching `output/` or `.anki-builder/`.
The deletion must therefore happen **on `main`**, as a v1 maintenance commit that `v2` then merges,
otherwise the branches diverge in tracked deck data, which is the exact failure that rule exists to
prevent.

2. **Does onboarding's config draft cost a paid whole-book pass**, like `conventions.md` does, or can

## Acceptance criteria

1. **The workflow is scripts.** Every phase runs as one script with ordered steps; the main thread
   authors no content and only verifies. Removing a step from a script is the only way to skip it.
2. **Every agent is pinned.** No role file omits `model` or `effort`; a missing pin fails the build.
   Adversary roles are pinned above the roles they check.
3. **No book coupling in code.** MET as of D4 (2026-09-06). All three publisher couplings now come
   from `book.json`: the vocabulary-table selector, the `enum`/`wnum` numbered-block markers, and the
   English lesson-label words.

   The grep this criterion first named was not usable as a gate: `class="sub"` matches a dashboard
   CSS class in `src/server/pages.js`, and the pattern also hits comments that DESCRIBE a coupling,
   which is the opposite of one. Excluding comment lines is what makes it a check rather than a
   reading exercise:

   ```sh
   grep -rn 'voca\b\|enum-\|wnum-' src/ | grep -vE '//|\*'
   grep -rn 'japanese-for-busy-people\|1fab0f99d1195ad9' src/ | grep -v '^src/evals/fixtures.js'
   ```

   The first must print nothing. The second may print only comments; `src/evals/fixtures.js` names
   the book deliberately, because a fixture with no input is not a fixture.

4. **Unknown, never zero.** Every book-dependent check, run against an EPUB with no config, reports
   _unknown_ rather than a clean pass. Demonstrated against a second EPUB.
5. **Rules compose.** One shared source of card rules is included by every prompt that writes cards,
   asserted by a test. The `する` / `まえに` case does not recur.
6. **Image verdicts persist.** Every image in a built chapter has a recorded verdict, so "nobody
   looked" is distinguishable from "nothing there".
7. **The learning pass closes.** Each unit keeps an immutable as-generated snapshot, and the pass
   reports every reviewer change attributed to the role that produced the item.
8. **Extras is bounded where it should be.** Miners are unbounded; the inventive author's output is
   about 20% of what the miners produced and contains no duplicate of theirs.
9. **Zero TTS re-spend.** No shipping card is ever refetched: its clip filename still matches the
   hash of the text its current derivation produces.

   The original wording said "100% cache hits", and measuring it showed that is the wrong invariant.
   Against the real deck the cache hit rate is **76%**, and that is not a regression: the cache is
   documented as disposable, `rm -rf .anki-builder/audio` is a sanctioned move whenever audio
   generation changes, and it has been dropped. The clips live in each unit's `audio/` directory
   (296 MB) rather than in the cache (171 MB).

   What must hold is that a card's shipping clip is still the one its text asks for, since a default
   clip is named for the hash of the text it speaks. `src/audio/refetchAudit.js` measures it, and
   hand-curated takes are counted separately because they keep their own filenames by design and
   folding them in would make the check cry wolf on 326 real cards.

   **Verified by:** `node scripts/build-audio.mjs <collectionDir> <n> --dry`, and across the whole
   book today: 2,062 current, 326 hand-curated, **0 would be refetched**.

10. **Ids are stable.** `deliver --dry` against a v2-rebuilt unit resolves every pre-existing card by
    its `abid:` tag, and the baseline guard does not fire.
11. **The base/extras split holds.** No base unit card is an utterance, enforced by a check that flags
    predicate-shaped targets in a base unit.
12. **Three gates, in order.** Extras cannot be authored before the base corpus review, and audio
    cannot run before the extras corpus review.
13. **`npm run ci` green**, plus `validate:decks` and `preflight` against the real collection.
